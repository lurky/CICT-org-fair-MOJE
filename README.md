## Run locally

Open this folder in VS Code and select **Unit 8 Org Fair (Contentful)** in Run and Debug, or run:

```powershell
flutter pub get
flutter run -d chrome --dart-define-from-file=cms.json
```

Without a CMS definition, the original starter's sample events are used. The drawer identifies the selected source. For the assignment evidence, run with Contentful.

## Later: your own public repository

Copy this project into a standalone repository you own, with `pubspec.yaml` at its root. Do not replace the remote of the class repository. Before committing, verify:

```powershell
git check-ignore cms.json android/key.properties
git ls-files cms.json android/key.properties
git status
```

Tracked results for configuration/signing files must be empty. Include web/, android/, and .github/workflows/ in the new repository. Generated caches and build output should remain ignored.

For Contentful, set repository Actions variables `CMS=contentful` and `CMS_SPACE` to your space ID, and secret `CMS_TOKEN` to the **read-only delivery token**. Settings > Pages > Source: GitHub Actions. The workflow includes the repository subpath as its base href. No repository has been created or deployed by this local setup.

Build-time CMS values become readable in compiled clients even if Actions stores the token as a secret. Never use a management/admin token in this app.

## Later: Android signing

Create and retain your own upload keystore outside the project. Copy `android/key.properties.example` to `android/key.properties`, fill in your passwords and key path locally, then build:

```powershell
flutter build apk --release --dart-define-from-file=cms.json
```

Output: `build/app/outputs/flutter-apk/app-release.apk`. No signing key or password is generated by this setup, and no signed release APK is claimed until that step is completed. Keep the keystore and passwords private and backed up; use redacted evidence when documenting setup.
